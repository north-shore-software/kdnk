# API direction

Written 2026-11-13, at the end of a design session. The design is agreed but **not implemented**.

## Read this first

`docs/quickstart.md` is **prescriptive**. It describes the API we want, not the one in the code.
It will not compile against the current code. This is deliberate, and it overrides the AGENTS.md
rule that a doc which disagrees with the code is a bug, for that one page, until the code catches
up. Do not "fix" the quickstart back to the current API, and do not report the mismatch as a bug.
Every other page in `docs/` is still descriptive.

The process the user set:

1. Shape the public API by editing `docs/quickstart.md` only. No code or doc-comment changes.
2. The user reviews it by leaving inline comments in the file.
3. Once the user is happy, implement the code to match. The AGENTS.md gate still applies:
   propose signatures, wait for sign-off, then implement, one API at a time.

## The spirit of the project

agent-smith is a Go library for building chat-agent apps on PocketBase. It is not an app. It
lets a developer define a few things and get a working, persistent, multi-user chat agent with
an HTTP API.

The app defines only:

- **collections**: the data the agent works with
- **a provider**: Gemini, Ollama, or a custom one
- **system prompt(s)**
- **tools**: custom ones, in addition to the ones generated from collections
- **session types**: each has its own set of collections and tools (deferred, see below)

Everything else is internal: auth, guests, conversation storage, the tool loop, streaming,
migrations, rate limits, pruning.

- **Collections are the crux.** Declaring a collection's name and fields must be enough to make
  it usable. CRUD and the model's tools for it come for free. In the user's words, the ergonomics
  of this are "kinda the crux of this whole project".
- **PocketBase may stay reachable, but stays out of the docs.** It's fine for advanced users to
  get at the PocketBase API, but the docs and hello world shouldn't show it.
- **The chat API is deliberately compatible with the Vercel AI SDK.** It speaks the UI message
  stream protocol, so a `useChat` frontend can talk to an agent-smith server.
- **The docs site is a feedback tool.** It's how the user reviews the framework while it evolves,
  and later it becomes the user documentation.

## The change in direction

Today (old) → agreed (new):

| Concern | Old | New |
|---|---|---|
| Entry point | `server.New(server.Config{Plugin: …})` returns `*pocketbase.PocketBase`; then `app.Start()` | `agentsmith.Run(setup)`; `setup` is `func(*agentsmith.Registry) error` |
| App definition | `plugin.Plugin` interface: `Name`, `Collections`, `SystemPrompt`, `Tools`, `ExecuteTool` | No plugin type. `setup` makes registry calls, as many times as it likes, or not at all |
| Provider | Global `llm.SetActiveModelSet`, `llm.SetProviderFactory`, `server.EnsureReady`, with model names fixed in `llm` | `r.Provider(&gemini.Provider{Model: "gemini-3.6-flash"})`, where the app names the model |
| System prompt | Method taking `ctx, core.App, Session` | `r.SystemPrompt(string)` |
| Collections | `[]*core.Collection` built by hand; the app writes the `owner` field and filters | `agentsmith.Collection[Note](r, "notes")`: fields come from the struct, and ownership is automatic |
| Collection access by the model | Hand-written tools plus a switch in `ExecuteTool` | Generated CRUD tools |
| Custom tools | `llm.Tool{Name, Description, Parameters: json.RawMessage}` plus a switch on name | `agentsmith.Tool(r, name, desc, handler)`: a typed handler with the schema generated from its argument type |
| Talking to it | curl plus `jq`, a guest token by hand, the raw wire format | `go run . chat` subcommand |

## Decisions made

Each of these was explicitly confirmed by the user.

**App shape**

- The app is a single setup function, `func(*Registry) error`. There is no plugin type, and
  `Name()` is dropped.
- Everything the app defines is registered there: provider, system prompt, collections, tools,
  and later session types.
- The registry is frozen once setup returns. Nothing can be registered at runtime.
- Registration functions can be called multiple times. For example, `agentsmith.Tool` once per
  tool.

**Tools**

- Tools are typed (option B). A handler receives a Go struct, and the JSON Schema is generated
  from that struct's type. A `jsonschema:"…"` tag gives the field description. `struct{}` means
  no arguments.
- Handlers return `(any, error)`, and the framework JSON-encodes the result.
- Tools are registered with a package function, `agentsmith.Tool(r, …)`, because Go methods can't
  have type parameters.

**Collections**

- A collection is declared from a Go struct (struct tags), for now.
- All CRUD tools are generated by default.
- A collection can be restricted to **append-only**, or to **system-writable**, which means
  read-only for the model and written only by app code.
- Scope is per user by default: every record belongs to its creator, and a user sees only their
  own. Other scopes come later.
- List is fetch-with-limit for now. Filtering will be needed later.

**Other**

- A `chat` subcommand replaces curl in the quickstart. It talks to the running server over the
  public HTTP API (`/api/guest`, then `/api/chat`).
- The AI SDK UI message stream stays the primary chat API.
- An **OpenAI-compatible endpoint** (`/v1/chat/completions`) is **planned but not built**, so that
  tools like `llm` (llm.datasette.io) and `aichat` can work. The quickstart has a `:::note` saying
  so. It would be a second endpoint, not a replacement. Known caveats from the discussion:
  - OpenAI clients are stateless: they send the full history and no conversation ID.
  - Server-side tool calls are invisible to those clients.
  - A client-sent system message has to be handled somehow.
  - Auth would still need a PocketBase token as the Bearer key, and that token expires.
  - The `model` field is a natural place to select a session type or provider.
- The quickstart's example app is **notes**, not todo, so that it doesn't overlap with
  `docs/examples/todo.md`. `get_time` stays in as the example of a custom tool that doesn't touch
  data.
- Session types are **ignored for now**.

## Open questions

These are in the quickstart as my guesses but have not been confirmed. Do not treat them as
decided.

- **Package name.** `agentsmith` at the module root. The import needs an alias because the module
  path has a hyphen.
- **Handler signature.** Currently `func(ctx, app core.App, s agentsmith.Session, in T) (any,
  error)`. `core.App` is the last PocketBase type left in hello world. **This is the next thing to
  shape:** what a handler receives instead. The likely answer is the session plus typed collection
  access, e.g. `notes.List(ctx, s)`, so that custom tools never touch `core.App` or `dbx`.
- **Generated tool names.** `notes_create`, `notes_list`, `notes_get`, `notes_update`,
  `notes_delete`.
- **List order.** With a limit, the order decides which records come back. My suggestion is newest
  first, using a hidden created timestamp on every record.
- **Restriction options.** The names and syntax aren't decided. Something like
  `agentsmith.Collection[Note](r, "notes", agentsmith.AppendOnly)`.
- **Provider per conversation.** The user said the provider is chosen per conversation. Who picks
  it isn't designed: the client, a Go callback, or a default per session type. `r.Provider` as
  written registers a single provider.
- **System prompts.** A fixed string is all the quickstart needs. Apps with per-user or
  per-conversation state need a dynamic form (today's API is a function of the session). "System
  prompt(s)", plural, probably ties into session types.
- **The `chat` subcommand.**
  - Over HTTP or in-process? As written it's HTTP, which needs two terminals.
  - Does each run make a new guest? That means notes from one run aren't visible in the next. The
    fix would be to persist the guest token.
  - Interactive only, or also a one-shot form?
- **Schema generation.** Take a dependency (e.g. `github.com/google/jsonschema-go`, as the Go MCP
  SDK does) or write our own? This is internal and doesn't affect the docs.
- **Setup errors.** What happens on duplicate names, invalid structs, or an error returned from
  `setup`?
- **Session types.** When they come back, the likely shape is that registration targets them, e.g.
  `st := r.SessionType("x"); agentsmith.Tool(st, …)`, with a bare `r` meaning "every session".
  How a conversation gets its type is open.
- **Framework-provided tools** beyond collection CRUD: none discussed.
- **Hiding packages.** Moving internals under `internal/` (or the root package wrapping them) has
  been proposed but **needs explicit approval**. Candidates are `chat`, `llm` internals, `server`
  routes, `httpx` and `migrations`.

## Implementation notes

- **The old public API is everywhere.** `plugin`, `server.Config`, the `llm` global registry, and
  `examples/todo`, `examples/rpg` and `examples/resume-builder` all use it. The examples will need
  porting.
  - `examples/rpg`'s `game_state` has `owner` and `conversation` fields, so it's per-conversation
    data. That makes it the natural test case for scopes beyond per-user.
  - `examples/resume-builder` is still a copy of the todo plugin.
- **Docs pages need follow-up once the code changes.**
  - `docs/plugins.md` is titled "Writing a plugin", but there is no plugin type in the new design,
    so it needs renaming.
  - `server.md` and `providers.md` will change too.
  - Per AGENTS.md, update doc comments and `docs/` in the same change as the code.
- **`docs/reference/` follows the code.** It's generated by gomarkdoc from these packages: `chat`,
  `gemini`, `llm`, `ollama`, `plugin`, `server`. The package list is in
  `docs/site/scripts/reference.mjs` and will need updating when packages move or are added.
- **Friction to remove in the implementation**, found while writing the original quickstart:
  - A missing API key produces an opaque "Llm stream failed." with nothing printed on stdout.
  - Hello world exposes PocketBase's command line and superuser link.

## Known bugs (user said "fix later")

- `gemini/gemini.go:197-224`: a second call to the same tool in one turn is collapsed or dropped.
- `ollama/ollama.go:185-188`: `Stream` never checks the HTTP status. On a non-200 response it
  yields an empty stream.
- `server/chat.go:106`: when the tool-step limit is hit, tool calls are left without output.
- `go.mod` pins `modernc.org/sqlite v1.44.3`. PocketBase v0.27.0 was tested against v1.37.0, so
  every downstream app prints PocketBase's sqlite version warning.
- The `chat` store functions ignore `ctx`.
- `httpx` breaks the AGENTS.md rule that every exported identifier gets a doc comment. It needs an
  exception, or a move to `internal/`.
- `gemini/gemini.go:178` and `ollama/ollama.go:247` have inline comments, which break the
  no-comments rule.
- gomarkdoc's source links point at GitHub `main`.
