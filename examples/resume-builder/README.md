# Resume Builder Example

## Overview
A career assistant that helps users build up a full audit of their experience through conversation (past roles, war stories, skills and contact details), then writes a resume tailored to a job description they drop in, using only what the audit records.

## What It Demonstrates
- **Static System Prompt**: Sets a fixed system prompt with `Registry.SystemPrompt`.
- **Several Collections**: `past_roles`, `war_stories`, `skills` and `job_descriptions` are declared with `kdnk.Collection` and give the model the generated create, list, get, update and delete tools for each.
- **Append-Only Collection**: `resumes` is declared with `kdnk.AppendOnly`, so the model gets only `resumes_create`, `resumes_list` and `resumes_get`. Every generated resume is a new record; none is edited or deleted.
- **Per-User Singleton**: `kdnk.Singleton[Profile]` stores the user's name, headline, contact details and links, and gives the model `profile_get` and `profile_set`.
- **Links Between Records**: `war_stories.role_id` and `resumes.job_description_id` hold record IDs as plain strings. Nothing enforces that they point at an existing record.
- **No Custom Tools**: Resumes are generated by the model reading the audit through the generated tools and writing the result with `resumes_create`.
- **User-Scoped Data**: Every record belongs to the user who created it, across all conversations.
- **Model Selection**: `KDNK_MODEL_SET` picks the provider: `local` (the default) uses `gemma4` on Ollama, `cloud` uses `gemini-3.6-flash` on Gemini.
- **React Web UI**: `web/` is a Vite project using TypeScript and React; `pnpm build` writes to `web/dist/app`, which `main.go` embeds and serves with `Registry.Web`.
- **Guest Auth**: The page signs itself in on load against `POST /api/guest`, which mints a `users` record with a server-generated `guestId` and a separate random password. The credentials live in `localStorage`; `POST /api/guest/upgrade` converts the same record into an email account, keeping its id and therefore its audit and resumes.

## What It Does NOT Demonstrate
- **Custom Tools**: There are no `kdnk.Tool` handlers.
- **Dynamic System Prompts**: The system prompt does not change between turns.
- **Rendered Resumes**: Resumes are stored as markdown and shown only as tool results in the chat.
- **Completeness Guarantees**: The model is told to list every role, war story and skill before writing a resume, but nothing checks that it did.
- **Durable Guest Sessions**: Clearing `localStorage` abandons the guest account permanently.
